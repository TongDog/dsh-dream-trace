# Dreaming：DeepSeek Harness 项目记忆插件

[项目主页与架构](README.md) · [English](README.en.md)

把项目中已完成的会话整理成可追溯、可纠正的长期记忆。支持手动复盘、后台复盘、带来源的记忆检索、后续会话自动加载索引及版本回滚。**0.2.0** 新增 dsh Web 侧栏中的「**记忆**」页面，可直接浏览和管理记忆。

兼容基线：**dsh 0.2.2-rc.1、Node.js >=24.9.0**。这是独立社区插件，不属于 DeepSeek 或 Anthropic 官方产品。只对该版本声明兼容。

本文介绍安装、使用和完整配置。模块职责、调用关系及写锁范围见[整体架构](README.md#整体架构)，运行结果与恢复方法见[数据与恢复](README.md#数据与恢复)。

## 安装

如果使用源码，先在本项目目录执行：

```sh
npm ci
npm run check
npm pack
```

在已有 dsh Web 配置中安装生成的包：

```sh
dsh plugin --profile web add /绝对路径/dsh-plugin-dreaming-0.2.0.tgz
```

也可以在 dsh 内让 `plugin_manager` 使用 `install_bundle` 安装本项目目录或包，具体以当前 dsh 工具支持的目标格式为准。插件不会自行改写用户配置。安装后重启 dsh，并刷新浏览器，确保加载新的服务端与界面代码。

初始 `projectRoots: []`，不会读取任何项目历史。新建工作区配置文件 `dreaming.patch.yml`，把路径换成实际存在的绝对目录：

```yaml
- id: dsh-plugin-dreaming
  config:
    projectRoots:
      - /绝对路径/你的项目
    storageDirectory: /绝对路径/dreaming-data
    provider: deepseek-official
    model: deepseek-flash
    autoRunAfterTurn: false
    afterTurnDelaySeconds: 30
    autoRunIntervalMinutes: 0
    verify: true
```

```sh
dsh web --patch /绝对路径/dreaming.patch.yml
```

模型通过 dsh 已配置的提供方调用，插件不保存 API 密钥。`provider` 和 `model` 必须与当前 dsh 的可用路由对应。若在图形界面修改插件设置，使用 dsh 的设置或配置编辑接口保存；覆盖配置会替换该插件的整份 `config`，未填写的字段使用默认值。

## 在界面中查看和管理记忆

打开 dsh Web 侧栏的「**记忆**」，在「项目」下拉框中选择已启用的项目。页面与智能体工具共用同一份数据和操作逻辑。

1. **查看概况。** 顶部显示「有效记忆」「有据可查」「待确认」和当前「版本」。有效记忆包括有据可查与待确认两类，不包括已退役记录。
2. **搜索与筛选。** 搜索框匹配标题、内容和证据原文。分类包括操作经验、项目决策、偏好、项目事实、踩坑记录；状态可以选择有效、有据可查、待确认、已退役或全部状态。默认只显示有效记忆。
3. **核对来源。** 点击左侧记录，在详情中查看完整内容、创建和更新时间、原文片段、来源类型、观察时间、会话编号和事件序号。编号用于定位原始记录，当前页面不直接跳转到原会话。
4. **运行复盘。** 在项目中完成对话后点击「开始复盘」，页面会显示新增、更新和退役数量，并重新读取当前版本。「刷新」可读取工具操作或后台复盘后的最新状态。
5. **移除或恢复。** 「移除这条记忆」需要再次确认，只影响当前记忆；「版本记录 → 恢复此版本」同样需要确认，会把所选内容和处理进度恢复为一个新版本。旧版本和原始对话仍然保留。

「尚未启用项目」表示需要先配置 `projectRoots`；项目中「还没有记忆」表示需要先完成对话并运行复盘。失败信息直接显示在页面中，操作失败不会显示为成功。记忆内容按普通文本显示，不执行其中的 HTML 或脚本。

可视化管理接口只允许已认证的 Harness 所有者访问，共享会话访客不能通过它列出项目、读取或修改记忆。项目选择仅接受配置中已有的准确根目录。Web 接入是可选功能：无界面或终端配置不需要加载侧栏和 API 网关，原有记忆工具与后台复盘仍可使用。

## 通过智能体工具使用

在启用的项目里完成至少一轮工作，再让 dsh「复盘这个项目的历史会话，更新长期记忆」，调用 `dream_run`。当前正在执行、尚未结束的回合不会参与这次复盘。

| 工具 | 用途 |
|---|---|
| `dream_run` | 处理一批尚未复盘的完整回合 |
| `dream_status` | 查看版本、处理状态、最近错误和可回滚版本 |
| `memory_search` | 用关键词检索记忆，支持中文子串 |
| `memory_read` | 按 ID 读取内容、来源、观察时间和可信程度 |
| `memory_forget` | 从当前记忆移除指定内容，保留历史版本 |
| `dream_rollback` | 将指定历史版本恢复成一个新版本 |

`deferred: true` 表示采集时发现还有完整回合超出本批预算，需要再次手动运行或等待下一次自动触发。设置 `autoRunAfterTurn: true` 可启用回合结束后的延迟复盘，或将 `autoRunIntervalMinutes` 设为正数启用周期复盘；两者默认关闭。后台模式同样遵守批量、输入、输出和超时限制。定时器只在 dsh Host 运行期间工作；关闭应用期间不会执行，也不补跑每一个错过的时间点。处理进度持久化，因此重新启动后仍能从已有游标继续。

`unchanged: true` 表示没有新前缀被处理，未调用模型也未生成版本；`unchanged: false` 且新增、更新、退役计数都为 0，则表示仅推进了处理游标。`dream_status` 的 `running` 和 `lastRun` 是进程内状态，重启后重置；记忆、游标和版本历史保留。

每次请求只加载短索引，详细内容通过记忆工具读取。索引带记忆版本，实际注入内容进入标准 dsh 会话日志，可在回放时核对。普通工具模式与 PTC 模式共用同一套工具；复盘工作会话单独使用无可用工具的执行环境。

## 记忆怎样产生

1. 按配置的项目范围查询原始会话事件，只选择完整回合，排除分叉继承部分、复盘工作会话、插件自己的记忆工具结果和注入上下文。
2. 保留用户原话、可见回答、工具调用与工具结果，过滤私有推理、图片和不透明数据；常见凭据模式会脱敏。
3. 模型对照旧记忆提出新增、修正或退役。每一条必须引用具体会话 ID、事件序号和原文片段。
4. 程序验证 JSON、引用、数量、长度和明显秘密；默认再运行一次独立语义复核，检查引用是否支持所表达的含义。
5. 全部成功后，一次提交记忆和处理游标。没有可用文本或模型返回空提案时，也会提交已处理前缀。提取、复核或发布前取消失败不会推进游标；发布后的结果不确定情况见下文恢复说明。

`supported` 表示引用的观察支持限定范围内的陈述，不等于独立验证的普遍事实；`uncertain` 保留不确定性；`stale` 不进入工具检索和注入索引，但仍可在界面的「已退役」筛选中查看。仅有模型自己的断言不能标为 `supported`。来源保留观察时间，便于判断规则是否依赖版本或时间。

跨项目隔离采取保守策略：只读取创建于允许项目的会话；一个回合如果切换到项目外，整个回合都不提取。其他项目创建的会话后来切入本项目，也不读取。所有子代理会话目前都排除。移动项目目录后需要显式配置新目录，旧记忆不会自动迁移。

## 配置

| 字段 | 默认值 | 说明 |
|---|---|---|
| `projectRoots` | `[]` | 允许读取的项目根目录；需存在，不可相互包含 |
| `storageDirectory` | `$DSH_HOME/dreaming`，未设置时为 `~/.dsh/dreaming` | 插件自己的数据目录 |
| `provider` / `model` | `deepseek-official` / `deepseek-flash` | 复盘和复核使用的 dsh 模型路由 |
| `autoRunAfterTurn` | `false` | 回合结束后延迟启动复盘 |
| `afterTurnDelaySeconds` | `30` | 连续回合合并等待时间 |
| `autoRunIntervalMinutes` | `0` | 周期复盘间隔；0 关闭 |
| `maxSessionsPerRun` | `10` | 一次选择的会话数量 |
| `maxEventsPerRun` | `2000` | 一次选择的证据事件数量 |
| `maxInputChars` | `60000` | 每次模型调用的 JSON 数据字符上限，不是 token 上限 |
| `maxProposalChars` | `12000` | 模型提案字符上限；为复核预留输入空间 |
| `maxFacts` | `100` | 当前有效记忆条数 |
| `maxFactChars` | `1800` | 单条内容字符上限 |
| `maxFactsPerRun` | `20` | 一次允许变更的记忆条数 |
| `maxIndexChars` | `4000` | 自动注入索引字符上限 |
| `maxOutputTokens` | `6000` | 每个复盘工作会话的输出上限 |
| `runTimeoutSeconds` | `180` | 一次操作的超时 |
| `searchLimit` | `20` | 默认及最大检索条数 |
| `verify` | `true` | 独立语义复核；关闭会减少模型调用但失去此检查 |

单个完整回合超过输入预算时会明确失败，不截断证据，也不跳过游标。按错误提示提高预算后重试。如果旧记忆占满输入空间，可移除不再需要的记忆或增加预算。字符限制只约束插件准备的数据，模型系统提示、dsh 必需上下文和提供方的计费 token 另计。

## 数据、恢复与边界

每个规范化项目路径经 SHA-256 生成独立数据子目录。`current.json` 指向不可变的 `revision-N.json`；版本通过内容校验和及历史链接校验，单写锁避免并发覆盖。记忆文件是 JSON，工具负责呈现；此版本不额外维护可能与主数据失去同步的 Markdown 副本或 Wiki。

提取和语义复核期间也持有项目写锁。同项目的重叠手动写操作返回 `BUSY`，应等当前操作结束后重试；读取仍可使用已发布版本。若返回 `COMMIT_UNKNOWN`，或写请求响应中断，应先刷新面板或调用 `dream_status` 核对当前版本：指针可能已经发布，不能仅凭错误判断写入未生效。

回滚会恢复该版本的内容和游标，后续证据可以重新处理。`memory_forget` 不是安全擦除：旧版本、原始 dsh 会话和复盘工作会话仍然保留相关历史。历史版本目前不自动裁剪，需关注数据目录大小。识别式脱敏无法保证发现所有秘密，启用项目范围意味着允许将所选历史发送到已配置的模型提供方。

插件卸载会清理注册、定时器并取消正在运行的工作；数据保留以便重新安装。进程突然中断后，未发布的临时版本不成为当前记忆，锁过期后可重试。长历史的底层完整日志查询仍有读取成本。

## 开发与验证

```sh
npm ci
npm run check
node scripts/verify-package.mjs
```

`npm run check` 依次执行类型检查、测试和构建；安装包核验脚本单独执行。构建先在 `lib/` 生成服务端 ESM 代码和类型声明，再用 esbuild 将 `client/source.js`、中英文文案和 Remote 校验器打包为发布用 `client.js`。修改界面应编辑 `client/source.js` 后重新构建。React 由 dsh 的浏览器模块表提供。

测试包括核心证据验证与恢复、项目隔离、真实 dsh Agent 循环的记忆注入与日志回放、工具参数和返回值、可选 Web 接口访问控制、取消及卸载。使用脚本化模型，不需要在线密钥；它证明插件机制，不证明某个线上模型的记忆质量或浏览器渲染效果。实际完成的检查详见 [兼容说明](docs/compatibility.md) 与 [验证记录](docs/verification.md)。
